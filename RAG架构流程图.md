# RAG 架构流程图（最新版）

## 写路径（文档入库）

```
用户上传文件
     │
     ▼
┌──────────────────────────────────────────────────────┐
│ 文档加载（保留原始格式）                               │
│  .md  → 直接读文件（保留 ## 语法）                     │
│  .txt → TextLoader                                    │
│  .pdf → 多模态提取（Vision 模型描述图片）              │
└──────────────────────────┬───────────────────────────┘
                           │
                           ▼
┌──────────────────────────────────────────────────────┐
│ txt 标准化（_normalize_txt_to_markdown）              │
│  "一、核心指标" → "## 一、核心指标"                    │
│  "第三章 故障" → "## 第三章 故障"                      │
│  分隔线（===）→ 删除                                  │
└──────────────────────────┬───────────────────────────┘
                           │
            ┌──────────────┴──────────────┐
            │                             │
            ▼                             ▼
┌─────────────────────┐     ┌─────────────────────────────────┐
│ 生成 Parent          │     │ 类型感知分块 → 生成 Child         │
│                     │     │                                 │
│ 文档 ≤ 3000字:      │     │  .md → 按 ## 标题切              │
│   整篇 = 1个Parent  │     │  .txt → 标准化后按 ## 切          │
│                     │     │  其他 → 语义分块                  │
│ 文档 > 3000字:      │     │        (embedding相似度断句)      │
│   按 ## 切多个Parent │     │                                 │
│                     │     │  + 标题粘连（## 不独立成句）       │
└──────────┬──────────┘     │  + 短块合并（< 50字合并相邻）     │
           │                │  + 超长兜底（> max_size 二次切）   │
           │                └──────────────┬──────────────────┘
           │                               │
           │                               ▼
           │                ┌────────────────────────────┐
           │                │ 上下文注入                   │
           │                │ "[文档：{filename}]\n" 前缀  │
           │                └──────────────┬─────────────┘
           │                               │
           │                               ▼
           │                ┌────────────────────────────┐
           │                │ 设置 metadata               │
           │                │  user_id, filename, md5     │
           │                │  parent_id → 指向所属Parent  │
           │                └──────────────┬─────────────┘
           │                               │
           ▼                               ▼
┌─────────────────────┐     ┌─────────────────────────────┐
│  ChromaDB            │     │  ChromaDB                    │
│  rag_parents         │     │  rag_collection              │
│  (原文, 按ID存取)    │     │  (小块, embed, 向量检索)      │
│  不做 embed          │     │  每块约 200 字               │
└─────────────────────┘     └─────────────────────────────┘
```

## 读路径（检索问答）

```
用户 Query
     │
     ▼
┌──────────────────────────────────────────────────────┐
│ ① HyDE 判断 (_should_skip_hyde)                      │
│                                                      │
│  简单 query（≤10字 或 短+精确疑问词）→ 直接用原文检索  │
│  复杂 query → LLM 生成假设文档，用假设文档的向量检索   │
└──────────────────────────┬───────────────────────────┘
                           │ search_text
                           ▼
┌──────────────────────────────────────────────────────┐
│ ② 混合检索 (HybridRetriever)                         │
│                                                      │
│  ┌─────────────────┐   ┌─────────────────────┐      │
│  │ 向量检索         │   │ BM25 关键词检索      │      │
│  │ ChromaDB         │   │ 内存倒排索引         │      │
│  │ (语义相似度)     │   │ (精确词匹配)        │      │
│  └────────┬────────┘   └──────────┬──────────┘      │
│           │                       │                  │
│           └───── 动态加权融合 ─────┘                  │
│                 短query → BM25权重 0.7               │
│                 长query → 向量权重 0.7               │
│                 + 笔记库并行检索 (notes_collection)   │
└──────────────────────────┬───────────────────────────┘
                           │ Top-K Child chunks (约5-6篇)
                           ▼
┌──────────────────────────────────────────────────────┐
│ ③ Reranker 精排 (BGE cross-encoder)                  │
│                                                      │
│  对每对 (query, child_chunk) 深度语义交互打分          │
│  Child 小块（200字）完全在 max_length=512 内          │
│  → 打分精准                                          │
│  按分数降序排列                                       │
└──────────────────────────┬───────────────────────────┘
                           │ 排序后的 Top-3 Child
                           ▼
┌──────────────────────────────────────────────────────┐
│ ④ Parent 解析 (_resolve_parents)                      │
│                                                      │
│  Top-3 Child → 收集 parent_id → 去重                  │
│  → 从 rag_parents 按 ID 取出完整 Parent 原文          │
│                                                      │
│  有 Parent → 用 Parent 送给 LLM（上下文完整）          │
│  无 Parent → 降级用 Child（向后兼容旧数据）            │
└──────────────────────────┬───────────────────────────┘
                           │ Parent docs (完整章节/文档)
                           ▼
┌──────────────────────────────────────────────────────┐
│ ⑤ LLM 摘要生成                                       │
│                                                      │
│  并发总结 Top-3 文档 → 合并多篇摘要 → 生成最终回答    │
│  超时 30s 兜底                                        │
└──────────────────────────┬───────────────────────────┘
                           │
                           ▼
                   返回给 Agent / 用户
```

## 存储架构

```
ChromaDB (persist: data/chromadb/)
├── rag_collection (Child)     ← 小块, ~200字, 带 embed, 向量检索用
│     metadata: user_id, filename, md5, parent_id
│
├── rag_parents (Parent)       ← 大块/整篇, 按 parent_id 存取, 送给 LLM
│     metadata: parent_id, filename, md5, user_id, type="parent"
│     不参与向量检索，只做按 ID 精确读取
│
└── notes_collection           ← 笔记向量, 用于跨源关联推荐

MySQL
├── users / notes / review_records / chat_sessions / chat_messages
└── (业务数据, 不参与向量检索)

Redis
└── 限流 / 缓存
```

## 各环节解决的问题

| 环节 | 解决的问题 | 实测数据 |
|------|-----------|----------|
| txt 标准化 | 纯文本无结构标题，子项被误切 | — |
| 类型感知分块 | .md表格/列表被切碎 | — |
| 上下文注入 | chunk 脱离来源后"星辰引擎"检索不到缓存数据 | Recall 20% → 100% |
| Parent-Child | 小块检索精准但 LLM 看不到完整上下文 | — |
| HyDE 跳过 | 简单 query 被 HyDE 膨胀引入噪声 | — |
| 混合检索 | 纯向量漏掉关键词精确匹配 | — |
| Reranker 在 Parent 前 | 对小块打分更精准（在512 token内），先淘汰噪声再取 Parent | — |

---

## 关键设计决策

| 决策 | 原因 |
|------|------|
| Reranker 在 Parent 解析之前 | Child 小块在 cross-encoder 的 max_length=512 内，打分精准；若对 Parent 打分会被截断 |
| Parent 默认整篇文档 | 个人知识库文档通常 < 3000 字，整篇给 LLM 信息最完整 |
| 超长退化为按章节切 Parent | 文档 > 3000字时避免超出 LLM 上下文限制或浪费 token |
| 旧数据向后兼容 | 无 parent_id 的 Child 自动降级为直接使用，不要求重新入库 |
| 两条入库路径都加逻辑 | 前端走 SSE 流式上传（knowledge_service.py），后端走 processor.py |

## 配置项 (chroma.yaml)

```yaml
collection_name: rag_collection          # Child collection
parent_collection_name: rag_parents      # Parent collection
persist_directory: data/chromadb
k: 3                                     # 检索 Top-K

chunk_size: 200                          # Child 目标大小
chunk_overlap: 20
separators: ["\n\n", "\n", "。", "！", "？", "!", "?", " ", ""]

parent_max_size: 3000                    # 超过此值按 ## 切多个 Parent
```
